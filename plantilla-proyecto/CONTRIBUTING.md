# Contribuir

Cada pull request debe explicar qué cambia, por qué y cómo se verificó. La documentación debe permitir comprender, configurar, probar, operar y mantener el producto.

Actualizar, según corresponda:

- comportamiento y alcance funcional;
- arquitectura, interfaces o flujo de datos;
- instalación, configuración y ejemplos de uso;
- comandos de prueba y evidencia reproducible;
- operación, diagnóstico, recuperación o migración;
- riesgos, limitaciones y aspectos aún no validados.

Si el cambio no requiere actualizar documentación, explicar el motivo en el PR. Si cambia el uso, la configuración o la operación del producto, actualizar las instrucciones correspondientes en el mismo PR.

Los ejemplos deben ser reproducibles y utilizar datos ficticios.

Consultar los requisitos y comandos de verificación del [README](README.md). Describir en el PR cualquier prueba pendiente o resultado inesperado. Actualizar `.gitignore` con las dependencias y salidas generadas de las herramientas que se incorporen, conservando código, pruebas, ejemplos y archivos de versiones de dependencias.
